# VoicePia 구조 이해

> 목적: "지금 있는 기본 코드가 어떤 명령으로 만들어졌고, Api/App/Core/Infrastructure/Shared가 어떻게 연결되는지"를 학습용으로 이해한다.

---

## 1) 지금 만들고 있는 것

VoicePia는 아래를 목표로 한다.

- 실시간 공동 집필 (동시 편집)
- AI 캐릭터 보이스
- 플롯 보드
- Windows / Mac 데스크탑 앱

현재 코드는 **기초 골격(스캐폴딩)** 단계다.  
즉, "기능 완성"이 아니라 "뼈대와 연결 방식"을 먼저 만든 상태다.

---

## 2) 기본 코드 생성에 사용한 명령

아래 명령으로 솔루션과 프로젝트를 만들었다.

```powershell
dotnet new sln -n Voicepia -o "c:\Voicepia"

dotnet new webapi -n Voicepia.Api -o "c:\Voicepia\src\Voicepia.Api" --use-controllers false
dotnet new maui-blazor -n Voicepia.App -o "c:\Voicepia\src\Voicepia.App"
dotnet new classlib -n Voicepia.Core -o "c:\Voicepia\src\Voicepia.Core"
dotnet new classlib -n Voicepia.Infrastructure -o "c:\Voicepia\src\Voicepia.Infrastructure"
dotnet new classlib -n Voicepia.Shared -o "c:\Voicepia\src\Voicepia.Shared"
```

생성 후 솔루션에 프로젝트를 등록했다.

```powershell
dotnet sln "c:\Voicepia\Voicepia.slnx" add `
  "c:\Voicepia\src\Voicepia.Api\Voicepia.Api.csproj" `
  "c:\Voicepia\src\Voicepia.App\Voicepia.App.csproj" `
  "c:\Voicepia\src\Voicepia.Core\Voicepia.Core.csproj" `
  "c:\Voicepia\src\Voicepia.Infrastructure\Voicepia.Infrastructure.csproj" `
  "c:\Voicepia\src\Voicepia.Shared\Voicepia.Shared.csproj"
```

그리고 프로젝트 간 참조를 연결했다.

```powershell
dotnet add "c:\Voicepia\src\Voicepia.Api\Voicepia.Api.csproj" reference `
  "c:\Voicepia\src\Voicepia.Core\Voicepia.Core.csproj" `
  "c:\Voicepia\src\Voicepia.Infrastructure\Voicepia.Infrastructure.csproj" `
  "c:\Voicepia\src\Voicepia.Shared\Voicepia.Shared.csproj"

dotnet add "c:\Voicepia\src\Voicepia.Infrastructure\Voicepia.Infrastructure.csproj" reference `
  "c:\Voicepia\src\Voicepia.Core\Voicepia.Core.csproj"

dotnet add "c:\Voicepia\src\Voicepia.App\Voicepia.App.csproj" reference `
  "c:\Voicepia\src\Voicepia.Shared\Voicepia.Shared.csproj"
```

추가 패키지:

```powershell
dotnet add "c:\Voicepia\src\Voicepia.App\Voicepia.App.csproj" package Microsoft.AspNetCore.SignalR.Client
```

## 3) 폴더/프로젝트 역할

```text
src/
  Voicepia.Api            서버 (REST + SignalR)
  Voicepia.App            MAUI Blazor 데스크탑 앱
  Voicepia.Core           도메인 모델
  Voicepia.Infrastructure DB/외부 연동 계층
  Voicepia.Shared         Api <-> App 공유 DTO
```

핵심 원칙:

- App은 DB에 직접 붙지 않는다.
- App -> Api -> DB 경로만 허용한다.

---

## 4) 상호 연결 방식 (중요)

### 4-1. 의존성(참조) 연결

- `Voicepia.Api` -> `Core`, `Infrastructure`, `Shared`
- `Voicepia.Infrastructure` -> `Core`
- `Voicepia.App` -> `Shared`

의미:

- `Core`는 가장 안쪽 도메인 모델
- `Infrastructure`는 Core를 실제 DB/외부 서비스와 연결
- `Api`는 요청을 받고 Core/Infrastructure를 사용
- `App`은 서버와 통신하며 Shared 타입을 공통 사용

### 4-2. 런타임 통신 연결

```text
[Voicepia.App] --HTTP/SignalR--> [Voicepia.Api] --> [DB]
```

- HTTP: 일반 CRUD API
- SignalR: 실시간 이벤트(입장/퇴장/편집 업데이트)

## 5) 코드 기준으로 보는 연결 포인트

### Api 시작점

`Voicepia.Api/Program.cs`

- `AddSignalR()`로 실시간 허브 활성화
- `/health` 엔드포인트로 서버 상태 확인
- `/hubs/document`에 `DocumentHub` 매핑

### 실시간 허브

`Voicepia.Api/Hubs/DocumentHub.cs`

- `JoinDocument(documentId, displayName)`
- `LeaveDocument(documentId)`
- `BroadcastEdit(documentId, byte[] update)`

문서 ID별 그룹(`document:{id}`)에 사용자를 묶어서, 같은 문서 참여자끼리 이벤트를 주고받는다.

### 앱 쪽 SignalR 클라이언트

`Voicepia.App/Services/DocumentHubService.cs`

- `HubConnectionBuilder().WithUrl(.../hubs/document)`
- `WithAutomaticReconnect()`로 재연결
- `JoinDocumentAsync()`로 허브 메서드 호출

## 7) "직접 구성해볼까 vs 따라갈까" (시니어 관점)

결론: **둘 다 한다. 단, 순서를 나눈다.**

### 추천 방식 (학습 효율 최고)

1. 먼저 현재 골격을 "그대로" 한 번 실행해 본다.  
   - 왜 돌아가는지 흐름 파악이 우선이다.
2. 그다음 같은 구조를 빈 폴더에서 "직접 다시 생성"해 본다.  
   - 명령/참조를 몸으로 익힌다.
3. 마지막으로 직접 만든 것과 현재 저장소를 비교한다.  
   - 차이를 보면서 이해가 고정된다.

### 왜 이 순서가 좋은가

- 처음부터 전부 직접 구성하면 작은 오타로도 막혀서 "구조 이해"보다 "환경 문제 해결"에 시간을 쓴다.
- 반대로 무작정 따라가기만 하면 왜 이렇게 나눴는지 이해가 약하다.
- 따라서 **실행 확인 -> 재구성 -> 비교**가 가장 빠르게 실력을 올린다.

### 직접 해볼 때 최소 목표

- 솔루션 + 5개 프로젝트 생성
- 프로젝트 참조 연결
- Api에서 SignalR Hub 매핑
- App에서 Hub 연결
- `/health` 응답 확인

이 5가지만 본인이 손으로 하면, 이후 DB/인증/CRDT 단계가 훨씬 쉬워진다.
